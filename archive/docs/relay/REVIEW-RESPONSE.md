## A. 設計と安全性

### 採用（設計を変えたもの）

| # | 指摘 | どう直したか |
|---|---|---|
| A1 | https のページから Tailscale の http は呼べない（mixed content）。中継の経路が丸ごと成立しない | **受信ホスト自身がスマホのページを配信する**構成に変更。同一生成元になり、mixed content も CORS も構造的に消えた |
| A2 | WebView2 のページが `file://` だと `crypto.subtle` が無く、SHA-256 も HMAC も動かない | https の仮想オリジンで配信。さらに実装中、仮想ホストのマッピングが `WebResourceRequested` を迂回することを実測したため、**C# がページのファイル自体を配信**する形にした |
| A3 | manifest の `root` / `label` がパス検証を通っていない | `root` は最初から持たない設計に。`label` は 1 セグメントとして同じ規則で検証 |
| A4 | `DCF2` の `name` は攻撃者由来で、`safeFileName` は `:` も RLO も通す | 書き込み側は `safeFileName` を使わず、TS と C# の両方で相対パス検証を通す。種別の判定は media type ではなく **`DCB1` の magic** |
| A5 | base64url + `|` はキーボードウェッジで壊れ、QR も英数字モードに乗らない | **base32（RFC 4648, 大文字）+ ハイフン**に変更。大文字化して読み戻すので Caps Lock でも壊れない |
| A6 | 6 桁のペアリングコードは総当たりできる | **10 文字 × 30 種（約 49 ビット）**、10 分、1 回限り、5 回失敗で**コードを破棄** |
| A7 | nonce が無いので ±120 秒のあいだ再送が通る | nonce を追加し、窓の中の使用済み nonce を保持。空 body も `SHA256("")` を必ず署名対象に |
| A8 | 本体を認証前に buffer している。上限も無い | **署名検証 → Content-Length 検査 → 読み込み**の順。上限超えは読む前に 413。読み込みにも上限と時間制限 |
| A9 | CORS が未定義 | 既定は同一生成元のみ。未知の Origin は 403。ペアリングは**常に**同一生成元のみ |
| A10 | manifest の数値を範囲検査の前に演算に使っている | 全ての数値を安全整数・上限で検査してから構造演算。走行合計にも上限 |
| A11 | パス検証の穴 5 件（`\`、ファイル/フォルダー衝突、Cf 文字、正規化、深さ） | 全て追加。`..` は「含む」ではなく**セグメント一致**に修正 |
| A12 | 文字列検査では既存の junction を越えられる | 解決後のパスを保存先と比較。各階層で reparse point を検査 |
| A13 | Windows でディレクトリの原子的 move はできない | **保存先の中**に staging を作り、同一フォルダー内の rename で確定 |
| A14 | hash-then-use の順序が未定義 | 「段 0」として明記し実装。`DCF2` の SHA-256 が通るまで中身に触れない |
| A15 | 64 MB は時間・記憶・再開不能の点で現実的でない | 既定上限を **16 MB** に。所要時間の目安を開始前に表示 |
| A17 | Tailscale の判定・IPv6・起動順・ACL の 4 つの誤り | `tailscale ip` で取得。両アドレス族を bind。systemd は `After=tailscaled` + 再試行。ACL を SETUP.md の必須手順に |
| A18 | `DCS1` に操作の輪が無い。枚数が非現実的 | 上限を **60 枚（約 48 KB）**に。受信側がマス目と**足りない番号**を出し、送信側にその番号を出してもらう形に |
| A19 | 受信物に Mark of the Web が付かない | Windows では付ける（best effort） |
| A20 | キーボードウェッジをグローバルフックで拾うのは keylogger | フックを使わない。読み取りモードのフォーカスした入力欄のみ。COM だけ C# |
| A21 | 失効の口が無い。時計ずれの復旧手段が無い | 端末側 `unpair` とホスト側 `device revoke`。401 にホストの時刻を載せ、クライアントは差分を学習して次で成功 |
| A22 | `DCS1` の CRC がペイロードだけを覆っている | **行全体**（docId・番号・枚数を含む）に変更 |
| A25 | Node の最低版が未指定 | `engines.node >= 20` |
| A26 | 4 ページ目の追加は上流の vite 設定を触る | **触らない**構成にした。スマホのページも PC のページも専用の vite 設定で別に組む |
| A27 | 脅威境界の文書が無い。秘匿性とスマホ侵害の行も無い | `ARCHITECTURE.md` を書き、両方を**非目標**として明記 |

### 採用しなかったもの

| # | 指摘 | 判断と理由 |
|---|---|---|
| A16 | バンドルの media type を `PRECOMPRESSED_TYPES` に足し、無駄な gzip 試行を止める | **不採用。** 止めれば `shared/protocol.ts` を変えることになり、「上流のワイヤーフォーマットに触らない」という一番大きな約束を崩す。指摘の実害（無駄な全長確保）は上限を 16 MB にしたことで最大 16 MB に収まり、テキスト主体のフォルダーでは gzip が実際に効く。**代わりに上限を下げるほうを採った** |
| A23 | CRC-32 は QR の ECC と重複、と読める書き方 | 指摘自体が「keystroke 経路には要る」と結論しており、実装は変えていない。**理由の書き方**を採用し、`slow-frames.ts` の冒頭に「QR は symbol を守る、CRC は行を守る」と明記した |
| A24 | 空フォルダー・更新日時・権限が運ばれない | **仕様として受け入れ、文書化した**（`USAGE.md`）。運ぶには manifest にディレクトリ項目と属性を足すことになり、一回転送の道具に対して形式が重くなる |

## B. UI / UX

### 採用

| # | 指摘 | どう直したか |
|---|---|---|
| B1 | 「設定」は入口ではない | 最上位は **送る／受け取る の 2 つ**。設定はトップバー右端のアイコンから |
| B2 | 「送る」1 画面に目的が 4 つ入っている | **選ぶ／表示中／終えた**の 3 画面に分割 |
| B3 | 「受け取る」の主操作が 2 つある | **方法を選ぶ／カメラ／リーダー／確かめて保存**の 4 画面に分割 |
| B4 | ファイルとフォルダーの分岐はモーダルの入れ子になる | 1 枚目に**実行ボタンを 2 つ並置**し、選んだ後は 1 つのカードに収束。下流は分岐しない |
| B5 | 骨格（topbar / レール / actionbar）が固定されていない | token 化して全画面共通に。主操作は常に右下 |
| B6 | 方向インジケーターが無い。中継の画面名は動詞で見分けられない | **常時・固定・同一書式**で追加。2 文字の要約＋ノードの順＋現在地の印の 3 重表示 |
| B7 | 「系統1 / 系統2」が画面に漏れる | 端末の**呼び名**（設定可能）と「向かいの画面／向かいのカメラ」に。系統という語は画面に出さない |
| B8 | 「再開」が 2 つの別物を指している | カメラは「最初から」、リーダーは「続きから」と**別々に名乗る** |
| B9 | ハッシュ不一致の専用画面が無い | 失敗画面を用意し、**1 行目を「1 件も保存していません」**にした |
| B10 | 保存先が書けないときの復旧画面が無い | 受信データを保持したまま「保存先を選び直す」を主操作に |
| B11 | リーダーの欠番表示が無い | マス目のグリッド＋**数字での名指し**（`あと 2 枚 ── 3, 6`） |
| B12 | 空状態が 3 つ無い | 初回（保存先が未作成）／受信先 0 件／登録コード期限切れ、それぞれ専用の文言と主操作 |
| B13 | 「カメラなし」を「拒否」と同じ赤で描いてはいけない | カメラなしは **warn 色・状態ドットも中立**。カードは消さず、理由を平文で隣に |
| B14 | 送信側は「完了」を名乗れない | 「**表示を終わりました**」＋「受け取れたかどうかは分かりません」 |
| B15 | QR が主役の画面に 2 カラムは間違い | 表示中だけ **1 カラム＋250px の細いレール**。1 マスあたりのピクセルが 3 を下回ったら「ウィンドウを大きくしてください」と出す |
| B16 | 狭窓と 125% は別の失敗 | 別々に撮影。狭窓は 1 カラムへ落とし、125% 相当は device pixel ratio を上げて撮った |
| B17 | グレーアウトの可否表 | 実装に反映。**押せない主操作には必ず理由**（`title`）。受信先 0 件・任意項目・危険操作はグレーにしない |
| B18 | トグルが列挙されていない | 「保存の前に中身を見せる」「同じ名前があったとき」の 2 つを、**現在の状態と切り替え後の効果を両方文章で**書く形に |
| B19 | 内部語彙の対応表 | 実装に反映。噴水符号・k・seq・blockLen・DCB1・manifest は通常画面に出さない。「1 枚あたりの量」「読み取りやすさ」「内容の照合」などに |
| B20 | 画面 × 状態の行列と証跡の対応 | `EVIDENCE.md` を撮影スクリプトの出力から生成する形にした（索引が実物とずれない） |

### 採用しなかったもの

| # | 指摘 | 判断と理由 |
|---|---|---|
| B18-5 | 「表示中は画面の明るさを最大にする」トグル | **不採用。** 表示中は常に画面ロックを抑止するだけにした。明るさは OS と端末の設定であり、トグルを増やすと「切り替えると何が変わるか」を正確に書けない（機種によって効かない）。**曖昧なトグルを置かない**という原則のほうを優先した |
| B18-4 | 「詳しい数値」をトグルにする | **不採用。** これは折り畳み（disclosure）であって二状態の設定ではない。部品の使い分けの原則に従い `<details>` にした |

## C. 実装後のコードレビュー（14 件）

計画レビューとは別に、**書き上げたコードそのもの**をレビューへ出しました。
全て採用し、直してあります。

| # | 何が起きるか | 直し方 |
|---|---|---|
| C1 | 認証のたびに `lastSeenAt` を書き戻すので、**別ターミナルでの失効が取り消される**。しかも端末が動いている最中に取り消される（＝失効させたい状況そのもの）。同様に、印刷したばかりの登録コードが `null` で上書きされる | 書き戻す前に読み直し、失効していたら書かない。書き込みは 1 分に 1 回まで |
| C2 | nonce を**署名の検証前**に消費していた。端末 id は秘密ではない（平文ヘッダーに載り、`device list` にも出る）ので、それだけで再送キャッシュを膨らませられ、観測した nonce を先取りして本物の要求を「二重送信」で落とせた | 署名を検証してから消費する |
| C3 | `serve` が 1 つの Server に 2 回 listen していて、2 本目が `ERR_SERVER_ALREADY_LISTEN`。**片方のアドレスでしか待ち受けず**、URL の代わりにエラーが出ていた（実ログで確認） | アドレスごとに Server を作る。実機で 2 本の Listen を確認 |
| C4 | 孤立サロゲートを TS は通し、C# は `IsNormalized` で**例外**。Linux では U+FFFD に潰れて 2 つの名前が 1 ファイルになる | 両方で拒否。`IsNormalized` は try/catch |
| C5 | 作成済みディレクトリの集合が大文字小文字を区別しており、`A/1.txt` と `a/2.txt` を含む**正当な**バンドルが Windows で EEXIST を起こして全体が失敗 | 衝突鍵で持つ |
| C6 | 一時保管の追い出しが `Dictionary` の列挙順を仮定しており、**6 回目のピックで、いま返したトークンを消していた** | 挿入順のリストで先頭から追い出す |
| C7 | 上限超過で `request.destroy()` していたため、**413 が届かなかった**。クライアントには ECONNRESET だけが見え、「上限を超えました」ではなく「つながりません」と出ていた | 破棄せず、`Connection: close` を付けた応答を返す |
| C8 | 試験用の口が環境変数だけで開き、しかも `--remote-allow-origins=*` を伴っていた | ポートを明示的に渡し、ワイルドカードを外した |
| C9 | staging 名が pid と時刻で予測でき、先に作られると全転送が失敗。失敗時に自分が作っていないパスを削除しうる | 乱数名にした |
| C10 | 出鱈目なコード 5 回で、**署名なしの誰でも**あらゆる登録コードを破棄できた | 形の合ったコードだけを失敗回数に数える |
| C11 | `dev-cert` が秘密鍵を `server.crt` に既定の権限で書いていた | 両方 0600 |
| C12 | 状態ファイルの一時名が固定で、プロセス間で競合すると破損した状態が公開されうる | プロセスごとに一意な名前 |
| C13 | コメントが参照していた TS/C# 照合テストが**存在しなかった** | `tests/path-parity.test.ts` を実装。実際に C# をコンパイルして 56 種の入力で突き合わせ、**その場で C4 の食い違いを検出した** |
| C14 | `/%ZZ` が 500 になる。Windows で `execFileSync` がカレントディレクトリの `tailscale.exe` を実行しうる | デコード失敗はアプリへ。絶対パスのみ実行 |

レビューが「問題なし」と明記した範囲: base32 の余りビット検証、`parseSlowFrame`
の CRC 再構成、署名対象と経路解決の一致（`..%2f`・`%2e%2e`・末尾スラッシュ・
重複クエリを実際に投げて確認）、`SafeWriter.Parse` のオーバーフロー処理、
`EnsureDirectoryChain` の停止性、`ServeFile` の脱出不能性、XSS 面。

## レビューでは出ず、実装中に見つけて直したもの

計画レビューは実装前なので、動かして初めて分かったものがあります。

| 何が起きたか | 直し方 |
|---|---|
| PowerShell 5.1 は BOM の無い `.ps1` を ANSI として読み、日本語が壊れて構文エラーになる | `.ps1` は UTF-8 **BOM 付き**で保存。コンソールの出力エンコーディングも UTF-8 に |
| `SetVirtualHostNameToFolderMapping` した仮想ホストへの要求は `WebResourceRequested` に届かない（実測） | 仮想ホストを使わず、C# がページのファイルも配信する |
| `fetchImpl = fetch` は receiver を失い、Chrome が "Illegal invocation" を返す | `(input, init) => fetch(input, init)` で包む |
| grid の行に名前を付けると、`display:none` の子が全ての行を 1 つずつずらす | shell を **flex 列**に。スマホの actionbar が画面中央に出る事故がこれ |
| PowerShell は既定で DPI 非対応。`GetWindowRect` は仮想座標、`CopyFromScreen` は実ピクセルで、150% の画面では 355px ずれた | `SetProcessDPIAware()` を最初に呼ぶ。寸法指定は DIP で受けて変換 |
| 上限を超える要求を本体を読まずに 413 で返すと、keep-alive のソケットに未読の本体が残り、次の要求が壊れる | 本体を読み切っていない応答には `Connection: close` |
| `enumerateDevices()` は許可前に空を返すことがあり、「カメラなし」の誤判定になる | 事前判定をやめ、`getUserMedia` の `NotFoundError` を正とする。列挙は**ヒント**にだけ使う |
| 書き込み可否の判定でプローブファイルを作ると、Windows では削除が遅延して受信フォルダーにゴミが残る | 作らずに問い合わせる（`accessSync` / 属性と列挙）。本当の答えは書き込み自体 |
| 最初の光学ループ試験は payload が 1 フレームに収まり、噴水符号を全く通っていなかった | 24 KB の非圧縮データにし、**16 枚以上復号したことを検査**に加えた |
