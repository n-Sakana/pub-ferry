## 1. 実カメラでの受信

**状態: 未確認。**

このデスクトップにはカメラがありません。それ自体は想定どおりで、
「カメラなし」の表示は**本物の状態をそのまま**撮ってあります
（`evidence/desktop/05-camera-none.png`）。

**擬似カメラも使えませんでした。** Chromium（1223 系）にも WebView2（151）にも
`--use-fake-device-for-media-capture` と `--use-file-for-fake-video-capture` を
渡しましたが、どちらも `getUserMedia` が `NotFoundError: Requested device not
found` を返します。この環境に映像デバイスの層そのものが無いためと思われます。
そのため `tests/optical-e2e.test.ts` は **理由を出して skip** します
（黙って通ることはありません）。

**代わりに確認したこと**: `tests/optical-loop.test.ts` が、カメラ以外の全ての
段を実物で通しています。フォルダー → バンドル → SHA-256 → 噴水符号 → QR 描画 →
**製品と同じ zxing デコーダーでの実復号** → 噴水復号 → コンテナ検証 →
バンドル検証 → **バイト一致**。欠落・破損・順不同も含みます。
置き換わっているのは光そのものだけです。

### 受入手順（カメラのある PC で）

1. `pc\pub-ferry.bat` を起動 →「受け取る」→「カメラで読み取る」
2. 別の端末で送信側を表示（スマホでも、もう 1 台の PC でも）
3. 進捗が上がり、「保存しました」が出て、保存先の中身が元と一致すること

**擬似カメラで自動確認したい場合**:

```
npm run build:relay-web
node --import tsx tools/make-qr-video.ts evidence/tmp/qr-stream.y4m 20
$env:PUB_FERRY_CHROMIUM = "<chrome.exe のパス>"
npm test          # optical-e2e が skip から実行に変わります
```

`skip` のままなら、その環境でも擬似カメラが使えていません。

## 2. 物理の二次元コードリーダー（HID / COM）

  検証済み。欠落・重複・順不同・CRC 破損・別文書混入・大文字小文字反転・

## 4. 実 Tailscale の複数端末間

**状態: 一部確認済み。この機械の側は実物で通っています。**

この機械には Tailscale が入っていたので、次は**実際に確かめました**:

実際の値はこの文書に載せません（tailnet 名も端末のアドレスも、公開する理由が
ないため）。確かめたのは次のことです。

| 確かめたこと | 結果 |
|---|---|
| `tailscale ip` からのアドレス取得 | 成功。CGNAT 範囲の IPv4 と `fd7a:115c:a1e0::/48` の IPv6 の**両方**が返る |
| MagicDNS 名の取得 | 成功。`<ホスト名>.<tailnet 名>.ts.net` の形で得られる |
| **両方のアドレスへの bind** | 成功。`Get-NetTCPConnection -LocalPort 8842 -State Listen` が 2 本 |
| スマホに出す URL の表示 | 成功 |

このうち「両方への bind」は、最初の実装では**失敗していました**。1 つの Server
に 2 回 listen していて 2 本目が `ERR_SERVER_ALREADY_LISTEN` になり、片方の
アドレスでしか待ち受けないままエラーだけを出していたのを、実際のログで見つけて
アドレスごとに Server を分けました。

**まだ確かめていないもの**:

- `tailscale cert` で作った証明書を、実機のスマホが警告なしで受け入れること
- 別の端末から MagicDNS 名で実際に届くこと
- tailnet の ACL でこの port を絞ったときの挙動
- Tailscale を止めた状態で `serve` が**起動せずに理由を出す**こと（コードは
  そうなっていますが、この機械では Tailscale が動いているため通っていません）

### 受入手順

1. 内側の PC で `npm run relay -- status` — 待ち受けアドレスと URL が出ること
2. `npm run relay -- serve` — 2 つのアドレスに listening と出ること
3. Tailscale を止めて `serve` — **起動せず、理由が出ること**
   （0.0.0.0 に落ちないこと。ここが要点です）
4. スマホから MagicDNS の URL を開き、**証明書の警告が出ないこと**
5. Tailscale の外の回線から同じ URL を開き、**届かないこと**
